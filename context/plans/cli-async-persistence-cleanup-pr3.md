# Plan: cli-async-persistence-cleanup-pr3

## Change summary

PR3 is the dead-code elimination and post-async cleanup that follows PR2 (PR #301, branch `remove-tokio-db-runtimes`, still open at head `f8e9c748`, itself based on `single-tokio-runtime`). PR2 removed the database-owned Tokio runtimes and migrated persistence to native async; its Deferred cleanup ledger in `context/plans/cli-async-turso-persistence-pr2.md` hands PR3 the redundant `async` wrappers, `run_with_retry_sync`, the redundant `drop(storage)`, stale `#[allow(dead_code)]` annotations, orphaned test support, the `join_three_to_completion` re-evaluation, the large-future/`recursion_limit = "256"` measurement and the temporary-index limitation.

An external investigation reported 114 compiler-reported unused items once dead-code suppressions are removed. That report is a seed investigation, not an authoritative inventory and not a deletion quota: its symbol-by-symbol listing is not committed to the repository, and its figures (114 items, 35 files with suppressions, 37 occurrences, 117 later `rg` matches) may use different counting conventions. **T01's reproducible, source-grounded compiler inventory, taken on the exact PR2 baseline, is the authoritative baseline for PR3.** T01 keeps the seed's classification leads (Category A retained `diff_traces` compatibility surface; Category B unwired mutation-cursor ref reconciliation and its dependencies; Category C superseded Agent Trace, repository identity, setup, sync and retry helpers; Category D unused database, path, doctor, hook, capability, configuration and mutation-trace helpers; and fields written but never read) and classifies every reproduced item. T02 deletes the verified Category C/D code and its suppressions, T03 applies the retain-and-defer disposition to the reconciliation cluster, T04 simplifies the remaining async layers, T05 audits blocking sites, future size and temporary-index cleanup, and T06 re-runs the unsuppressed audit and prepares the validation and PR4 handoff. Full validation is a separate `/validate` gate after T06.

**Stacking.** PR3 is a stacked PR. The working branch `dead-code-blues` currently sits exactly at the PR2 head (`f8e9c748`), so every PR3 diff and review is taken against `remove-tokio-db-runtimes` (`git diff remove-tokio-db-runtimes...HEAD`), never against `main`, so the PR2 migration is not re-reviewed. If PR2 merges first, rebase onto its integration branch and keep the same commit range.

**Reconciliation default: retain and defer.** Evidence in the current code and context: `pin_tree` is called only from `coordinator.rs`, nothing in production deletes pins, and `ref_reconciliation` has no caller (`mod ref_reconciliation;` is private; `context/cli/mutation-trace-ref-reconciliation.md` says invocation timing belongs to a later "harness-wiring PR"). The implementation and its integration path are already planned in `context/plans/mutation-cursor-ref-reconciliation.md`, and a separate `ref-rec` branch carries related reconciliation work. So pins left by crashed or failed `coordinate()` paths accumulate until a manual `git update-ref -d`; this documented consequence is accepted. PR3 therefore retains the reconciliation implementation and the helper APIs it needs, narrows suppressions to justified declarations, records that it remains unwired, and does not wire it. No new approval and no new ADR are required for this default; durable context and a reference to the existing reconciliation plan suffice. A new user or architecture decision is needed only if T01 finds material new evidence that invalidates retain-and-defer.

### Verification modes

- **Diagnostic mode (T01, T06, optionally T05):** in an isolated `git worktree`, temporarily remove dead-code suppressions, compile the non-test binary and the test targets (`cargo test --no-run`), capture warnings/errors, identify unused declarations, and record diagnostics with their build-target and platform context. A nonzero exit caused solely by expected dead-code diagnostics (the project compiles with `-D warnings`) is an expected audit outcome, not a verification failure. Other compiler failures are investigated, not counted as dead code. Discard the worktree safely (`git worktree remove`), never with destructive restore commands against the main worktree.
- **Normal verification mode (T02–T05 focused checks and `/validate`):** with the intentionally retained, narrowly scoped suppressions restored, the binary and test targets compile, clippy passes with warnings denied and the normal validation checks pass. Unrelated warnings are never suppressed and compiler lint settings are never weakened.

## Constraints and non-goals

- **In scope:** `cli/src` dead-code and suppression cleanup; deleting verified-dead production code and the tests/fixtures that only exercised it; `resilience.rs`, `db/mod.rs`, `sync/sync.rs`, service forwarding and hook/lifecycle helper simplification; measurement/audit of futures, `spawn_blocking` sites and temporary Git indexes; durable context updates for the above.
- **Out of scope:** the macOS guarded-shell `pipe()`/`fcntl()` race fix; implementing or wiring ref reconciliation; new mutation-cursor semantics; database schema migrations; retry policy changes; OpenTelemetry (PR4); broad test-suite restoration; new generic execution or persistence abstractions; removal of the `diff_traces` compatibility surface (separate planned phase); full repository validation (owned by the final `/validate` gate).
- **Constraints:** the baseline is PR2 head `f8e9c748` on `remove-tokio-db-runtimes`; all diffs are measured against that branch. All tools run through Nix per `AGENTS.md` (`nix develop -c ./scripts/run-cli-cargo.sh ...`, `nix shell nixpkgs#ripgrep -c rg`); no host `rg`, `cargo`, `python3`. Reproduction and the unsuppressed build run in a disposable `git worktree`/copy, never with destructive restore commands (`git checkout .`, `git reset --hard`) against the main worktree. Repository conventions apply: no code comments except documented-exception reasons required by this plan's suppression policy (user preference is comment-free code, so an exception's reason lives in the attribute's `reason = "..."` string or the owning context doc rather than prose comments — T01 confirms the repo's lint level accepts `reason`), exact-pinned dependency versions unchanged, minimal focused tests only.
- **Constraints (preservation):** keep static dispatch and associated-type capability boundaries; do not add dynamic dispatch; preserve fail-closed recovery in mutation-scope adapters; do not delete platform-gated code on Linux-only evidence; written-but-never-read state fields are removed only after checking serialization, derives, Debug, Drop, tests and protocol transitions.
- **Non-goal:** preserving unused APIs for hypothetical future flexibility, or converting dead production code to `#[cfg(test)]` merely to keep obsolete tests alive.
- **Non-goal:** meeting a deletion count or reproducing the seed report's 114; the reproduced inventory is the baseline and no rows are invented to reach any number.
- **Non-goal:** restoring deleted ordinary test suites for coverage parity.
- **Non-goal:** deleting the reconciliation cluster to shrink the dead-code count, or wiring it into production in PR3.
- **Constraint (compatibility):** the `diff_traces` compatibility contract in `context/decisions/2026-10-01-retire-diff-traces-remote-sync-compatibility-gate.md` is preserved; intentionally unused compatibility declarations are retained with narrow exceptions rather than deleted.
